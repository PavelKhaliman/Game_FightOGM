# FIGHTOGM

**Производство не останавливается.** Нативный локальный 3D-файтинг на Go и raylib.
Два игрока на одной клавиатуре, десять бойцов из исходных GLB, раунды по 99 секунд,
победа в матче после двух выигранных раундов. Интерфейс полностью на русском.

## Быстрый запуск Windows x64

Запустите **`run.bat`** или **`dist/FightOGM.exe`**. В готовой папке `dist` есть
исполняемый файл и все необходимые модели. Эту папку можно целиком перенести
на другой компьютер; для готовой сборки Go и GCC не нужны.

В меню: стрелки / W S, Enter; кнопки также доступны мышью.
В выборе бойцов игрок 1 подтверждает **F**, игрок 2 — **J**.
Каждый выбирает независимо; одинаковые персонажи разрешены.

## Сборка

- Windows x64, OpenGL 3.3 и установленный драйвер видеокарты.
- Go **1.23 или новее**. Проверенная версия: 1.23.1.
- MinGW-w64 GCC в PATH, например `C:\msys64\mingw64\bin`.
- `github.com/gen2brain/raylib-go/raylib` **v0.55.1**, зафиксирован в go.mod.
- При первой сборке нужен доступ к серверу Go-модулей. Raylib компилируется
  вместе с игрой через cgo, отдельная установка raylib / DLL не нужна.

```powershell
.\build.bat
.\run.bat
```

`build.bat` запускает тесты, проверяет `go build ./...`, собирает
`dist/FightOGM.exe` и копирует модели. Кэши сборки помещаются в `.tools`.
Настройки существующего игрока сборка не перезаписывает.

Стандартные команды для среды с доступным Go-кэшем:

```sh
go build ./...
go test ./...
go run ./cmd/fightogm
make build
make run
```

При наличии ограничений доступа к стандартному Go-кэшу используйте `build.bat`.
`run.bat` запускает уже собранный файл; после изменения исходников сначала пересоберите игру.

Код не использует Windows API в игровой логике. Для Linux потребуются GCC,
заголовки OpenGL и зависимости GLFW / X11 / Wayland согласно
[инструкции raylib-go](https://github.com/gen2brain/raylib-go).
Linux-сборка в этой среде не проверялась.

## Управление

| Действие | Игрок 1 | Игрок 2 |
|---|---|---|
| Влево / вправо | A / D | ← / → |
| Прыжок / присед | W / S | ↑ / ↓ |
| Шаг в глубину / к камере | Q / E | U / M |
| Лёгкий удар | F | J |
| Сильный удар | G | K |
| Удар ногой | H | L |
| Захват вблизи | F + G | J + K |
| Блок | удерживать R | удерживать O |
| Специальный приём | T | P |
| Защитный / второй приём | R + T | O + P |
| Суперприём | Y | I |
| Пауза | Esc | Esc |
| Полный экран | Alt + Enter | Alt + Enter |
| Отладка | F3 | F3 |

Присед + удар ногой выполняет подсечку. Движение к сопернику + сильный удар —
производственный хук. Захват проходит через блок, но не ловит прыгающего бойца.
Лёгкий удар можно продолжить сильным, затем ударом ногой. Буфер хранит нажатие
135 мс игрового времени. Раннее нажатие следующего удара перед окончанием
восстановления не теряется. Блок полностью отменяет лёгкие удары; тяжёлые и
специальные могут нанести небольшой урон сквозь защиту.

Энергия накапливается при попаданиях и получении урона. Суперприём требует 100%.
Захваты-суперприёмы Гаглоева и Елхимова активируются только вблизи.
Если время истекло, побеждает боец с большим числом HP. При равенстве или
одновременном нокауте раунд переигрывается без начисления победы.

Пассивные свойства и разные характеристики заданы в `internal/characters/roster.go`.
Иванов получил новую геометрию лица и тела, текстуры кожи, волос и одежды по
фотографии и модельному листу. Его исходный скелет и все 18 клипов сохранены.
Остальные девять бойцов пока используют исходные прототипные модели.
Сложные постановочные захваты представлены
исходными клипами, игровым броском, короткой сменой камеры и эффектами.

## Настройки и файлы

- `config/settings.json` — создаётся при сохранении настроек / выходе в папке
  найденных игровых ресурсов. При запуске из `dist` это `dist/config/settings.json`.
- Разрешение: 1280×720, 1600×900, 1920×1080, 2560×1440; окно можно растягивать.
- Внутренний кадр — 1600×900 с сохранением пропорций, координаты мыши учитывают поля.
- Общая громкость, музыка, эффекты, полный экран сохраняются в JSON.
- `key_bindings` содержит коды клавиш raylib и допускает ручное переназначение.
- `logs/fightogm.log` — журнал последнего запуска.
- `assets/models` — десять игровых GLB и обязательный манифест.
- `assets/references` — фотографии и модельные листы; в рендеринге не используются.
- `assets/source/ivanov` — текстуры, измерения лица и описание сборки нового Иванова.
- `assets/source/original-models/ivanov.glb` — резервная копия исходного Иванова.
- `assets/audio` — необязательные WAV и `music.ogg`. При отсутствии WAV игра
  синтезирует короткие сигналы. Музыкальный трек в комплект не входит.

Поиск ресурсов: текущая папка, папка исполняемого файла, её родитель.
Для явного пути: `FightOGM.exe -assets-root "D:\FightOGM"`.
При повреждённой модели боец помечается недоступным, остальные работают.

## Устройство проекта

```text
cmd/fightogm       точка входа, основной поток OpenGL
internal/app      экраны, цикл приложения, проверка реального рендера
internal/game     симуляция 120 Гц, матч, урон, блок, способности
internal/fighter  состояние бойца, определения, характеристики
internal/characters  данные десяти бойцов и приёмов
internal/combat   геометрия hitbox / hurtbox, события, счётчик серии
internal/input    единый опрос клавиатуры, привязки, буфер команд
internal/assets   GLB-метаданные, проверка манифеста, контроллер анимации
internal/render   камера, арена, освещение, тени, реквизит, эффекты
internal/ui       русский шрифт, меню, выбор, HUD, управление
internal/audio    необязательные аудиофайлы и синтез эффектов
internal/config   сохранение настроек
```

Симуляция выполняется с постоянным шагом 1/120 с, рендеринг ограничен 60 кадрами/с.
Столкновения используют сферы, не треугольники моделей. Каждый экземпляр приёма
имеет номер; попадание учитывается один раз на активное окно, многоударные приёмы
имеют отдельные окна. Модели и анимации двух игроков размещены независимо,
включая зеркальные бои. Пауза останавливает таймер, физику и анимации.

### Анимации

`LoadModelAnimations` читает настоящие клипы из GLB. `AnimationSet.ByName`
централизует имена. Длительности читаются из JSON-секции GLB; контроллер
синхронизирует весь клип с длительностью приёма, зацикливает idle / walk и
не перезапускает их каждый кадр. Ось Z исходных моделей переводится в Y.
Скелет и ключевые кадры не заменяются процедурной анимацией.

В начале запуска проверяются все базовые и специальные клипы манифеста.
Отсутствующий базовый клип делает бойца недоступным; отсутствующий специальный
явно записывается в журнал и визуально заменяется `special_pose`.

### Добавить или изменить бойца

1. Положить GLB со скелетом и анимациями в `assets/models`.
2. Заполнить запись в `special_animation_manifest.json`.
3. Добавить `fighter.Definition` в `characters.Roster`: идентификатор, русское имя,
   путь, HP, скорость, силу, защиту и приёмы. Текущая игра рассчитана на 10 карточек;
   при расширении ростера потребуется изменить сетку и тест количества бойцов.
4. Специфическую механику добавлять небольшим обработчиком статуса / события в
   `game`, сохраняя общую логику боя для всех персонажей.

### Пересобрать модель Иванова

Обычная сборка игры использует готовый `assets/models/ivanov.glb` и не требует
Python. Для изменения геометрии есть `scripts/art/build_ivanov.py`; он сохраняет
узлы, скелет, анимации и их двоичные данные из резервной копии GLB.
Порядок работы и исходные промпты: [assets/source/ivanov/README.md](assets/source/ivanov/README.md).

```sh
python scripts/art/build_ivanov.py
go run ./cmd/modelreview -compare assets/source/original-models/ivanov.glb
```

Снимки реальной модели в семи ракурсах и сравнение сохраняются в
`test-output/ivanov`. Проверка анимаций `-smoke-test` охватывает все части модели,
включая лицо, волосы, одежду и руки. Загрузчик создаёт mipmaps для мелких текстур
и освобождает принадлежащие модели текстуры при смене боя.

### Добавить анимацию или приём

1. Экспортировать именованный клип внутри GLB и внести имя в манифест.
2. В определении приёма указать `Animation`, фазы `Startup / Active / Recovery`,
   урон, оглушение, отбрасывание, стоимость, перезарядку и объёмы попадания.
3. Для снарядов, реквизита и усилений добавить `MoveEvent` с явным временем.
4. Проверить анимацию и сферы через F3. Индексы анимаций не вписывать в боевой код.

## Проверки

```sh
go test ./...
go vet ./...
go run ./cmd/fightogm -smoke-test -output test-output
```

Тесты проверяют урон без повторных попаданий, блок и захват, буфер ввода,
серии, перезарядки, раунды, ничьи, способности, пассивные свойства и настройки.

`-smoke-test` открывает скрытое **настоящее окно OpenGL**: загружает все модели,
проверяет изменение вершин во всех 171 клипе, правильное положение моделей,
проходит выбор → бой → два раунда → результат → реванш, проверяет паузу,
зеркальный бой и рендеринг всех суперприёмов. Сохраняет снимки экранов и
`test-output/report.json`, возвращает ненулевой код при ошибке.

F3 показывает частоту кадров, состояние, анимацию и её прогресс, HP, энергию,
позицию, скорость, текущий приём, зелёные объёмы тела и красные зоны атак.
